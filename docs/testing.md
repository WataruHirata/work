# テスト方針

## 原則

- 要件ID・業務不変条件・受入条件からテストを設計し、各テストに要件ID（FR/NFR/AT）を紐付ける。
- 金額、税、営業日、権限、承認、締め、再取込、特売復帰、移行照合は正常系・境界値・異常系・権限外を扱う。
- 同じ入力を再実行しても結果が不正に変わらないことを検証する。時刻・外部連携・データは制御可能なテストダブルを使う。
- テストは架空データで実行し、実店舗データ、個人情報、認証情報を含めない。
- 不安定なテストは原因を修正し、恒常的な再試行で失敗を隠さない。

## テストレベル

| レベル | 対象 | 主な検証 |
|---|---|---|
| 単体 | 営業日判定、金額・税計算、状態遷移、認可規則 | 境界時刻、端数、返品/取消、権限、月次確定 |
| 統合 | DB、ファイル取込、バッチ、認証、通知 | 重複・部分失敗・再処理・トランザクション・監査 |
| UI/E2E | ポータル、締め、修正承認、特売、出力 | 権限別導線、キーボード、失敗回復、動き抑制 |
| 受入 | 業務代表者が行う要件書のAT | 店舗類型、業務手順、移行照合、先行10店舗 |
| 非機能 | 本番相当環境の性能・回復・セキュリティ | ピーク負荷、夜間連携競合、RTO/RPO、アクセス制御 |

## 要件書に定義された受入試験

| ID | 検証観点 |
|---|---|
| AT-01 | 全112店舗のPOS取込、未受信、重複、再取込、形式不正 |
| AT-02 | 標準、24時間、モール、駅前店舗の営業日境界 |
| AT-03 | 店舗・エリア・全店集計、前年比、客数、客単価、粗利 |
| AT-04 | 締め前、当日、翌日以降、月次確定後の変更制御 |
| AT-05 | 一次・最終承認、差戻し、権限外操作拒否 |
| AT-06 | 8%/10%税率、イートイン、税込後円未満切捨て |
| AT-07 | 見切り、チラシ、タイムセール、通常価格復帰、失敗通知 |
| AT-08 | 当日取消、後日返品、理由、承認、マイナス計上 |
| AT-09 | 発注入力・連携・エラー（承認された対象範囲のみ） |
| AT-10 | ロール、データ範囲、共用PCでの個人識別、変更前後監査 |
| AT-11 | 同時接続、応答時間の測定条件、夜間バッチ競合 |
| AT-12 | 件数、金額、マスタ、履歴、権限の移行照合 |

数値目標の多くは提案・未確定である。AT-11や稼働率・復旧試験の合否閾値は、測定環境と業務責任者の承認を記録してからゲートにする。

## UX・モーション検証

[UI・モーション方針](./ui-motion.md)に従い、アニメーションの有無、`prefers-reduced-motion`、画面読み上げ、キーボード、グラフの元値一致、負荷を確認する。画面変更PRでは必要に応じて静止画・動画を添付する。

## 現在の自動テスト

要件書の機能要件・トレーサビリティ表・受入試験IDはPython標準ライブラリで検査する。営業日・税の業務ロジックとDBマイグレーション/RLSはVitestとPGliteで検査し、GitHub ActionsではSupabase CLIでもローカルPostgreSQLに対するマイグレーション適用・Lintを実行する。特売DBテストでは複数商品/店舗の下書き作成、未確認EDLP分類での公開拒否、商品本部のみの公開、店舗別RLS、店舗確認・作業記録を検証する。ログインや特売画面のSupabase実環境認証・E2Eは未実装であり、本番POS連携も未検証。

```powershell
python -m unittest discover -s tests -v
npm test
```
