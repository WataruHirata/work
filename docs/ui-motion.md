# UI・アニメーション方針

## 体験目標

店舗の共用PC、PC操作に不慣れな利用者、売場の忙しい業務を前提に、短い操作で確実に業務を完了できるようにする。アニメーションは画面構造の理解、操作結果の伝達、売上などの数値の把握を助けるために積極的に使う。ただし、正確さ、操作速度、可読性、アクセシビリティを優先する。

## 動きを使う場所

- **画面遷移**: パネルの展開、タブ・フィルター変更、モーダルの出入りに短いトランジションを使い、画面上の位置関係を保つ。
- **操作フィードバック**: 保存、締め、承認、取込・再処理の開始・成功・失敗・待機を、状態ラベル、アイコン、控えめな動きで示す。処理中は二重送信を防ぐ。
- **インフォグラフィック**: 売上、前年比、客数、客単価、粗利、値引、廃棄、特売効果の表示で、棒・折れ線・構成比などのグラフを段階的に描画し、比較対象への視線を導く。
- **ダッシュボード**: 初期表示時やフィルター変更後の数値変化は、元値と新値を識別できる短い補間で示す。頻繁な自動更新で動き続ける画面にはしない。
- **状態の連続性**: 展開・折りたたみやドリルダウンは、利用者がどの店舗・営業日・集計から移動したか追える遷移にする。

## 実装・アクセシビリティ基準

- `prefers-reduced-motion`を尊重し、アニメーションの抑制・置換ができること。動きの抑制時も値、状態、操作結果は完全に同じ情報量で表示する。
- 色、動き、音だけを状態や数値の唯一の表現にしない。ラベル、数値、形状、パターン等を併用する。
- 点滅、急なズーム、視差、不要なループ、自動再生する装飾を避ける。自動更新や長い動きを停止できるようにする。
- キーボード操作、フォーカス順、フォーカス表示、スクリーンリーダー用の名称と値を保つ。グラフは要約とアクセス可能な表またはデータ一覧を提供する。
- 軸、単位、期間、対象店舗、凡例、速報/確定状態を表示する。アニメーション中も確定値と仮値を混同させない。
- 操作確認・取消が必要な金額操作では、演出が確認ステップや操作時間を邪魔しないこと。
- モーションは共通トークン（速度・イージング）で管理し、画面ごとの過剰なばらつきを防ぐ。具体値は採用UI技術の選定後に定義する。

## 検証

- モーションあり・抑制設定ありの両方で、視覚、キーボード、支援技術を確認する。
- 初回表示、フィルター変更、データ再取得、ゼロ値、欠損、エラー、通信遅延を確認する。
- 112店舗・締めピーク・想定同時利用数を踏まえ、アニメーション中に描画が重くならないか測定する。
- グラフの値が元データと一致することをテストし、色・アニメーションに依存しない読み取り手段を確認する。
- 売上、締め、承認などの主要フローは、動きなしでも同じ手順で完了できること。
