# 実装ロードマップ

このロードマップは、要件定義書の未確定事項を隠さず、依存関係の少ない作業から完了判定できるように整理したものです。「実装済み」は稼働中の連携・業務機能を意味せず、各段階の受入条件を満たしてから更新します。

**状態: 基盤コードを実装。Vercel/Supabaseの実プロジェクト設定とProductionリリースは未完了。**

- Next.js/TypeScriptアプリ、操作可能なダッシュボード画面とモーション/縮小モーション対応を追加。
- 売上営業日判定、税込合計の端数切捨てを含む単体テストを追加。
- Supabase PostgreSQLの組織・店舗・売場・権限、商品価格、特売、売上・締め、修正承認、通知、バッチ、発注、監査の初期スキーマを追加。

- Productionは明示的なリリース準備変数と保護環境の設定まで無効にし、DB適用成功後にVercelへデプロイする構成を追加。

## M4 — 特売・値引・税・返品

**状態: 複数商品・複数店舗の特売下書き作成画面、下書き公開、店舗選択、商品・店舗別の確認/売場作業状態を実装。DB認可・監査テストあり。実Supabaseでの受入は未実施。**

- 新要件では通常売価マスタを新設せず、既存の通常売価を参照する。参照元・POS IFが確定するまでは価格比較と自動配信・復帰を有効化しない。
- EDLP対象外を確認する参照元も未確定のため、商品適格性は `not_configured` を初期値とし、確認済みでない商品を含む特売はDB側で公開拒否する。
- 特売ごとに複数商品・店舗を設定し、POS反映状態と値札・POP・売場表示の変更/復帰作業を商品・店舗単位で別管理する。現段階のPOS状態は `not_configured` であり、実連携を装わない。
- 店舗確認と作業完了を担当店舗の利用者に限定し、監査履歴を残す。
- 作成、公開、店舗確認、開始時/終了時の作業記録画面を追加。通知、差異管理、手動POS結果登録、再処理は未実装。
- 店舗判断の見切り・タイムセール、返品・取消、レジ金過不足。
- 税率・端数処理を業務ルールとPOS連携に対して照合。
- FR-012、F-10-016〜109、NFR-20〜34、AT-07、Q-12/Q-15〜17に対応。

**着手ブロッカー:** EDLP対象判定の参照元、POSへの価格反映経路・結果取得・通常売価参照元・価格優先順位（Q-15〜17）、32店舗のイートイン変更手順（Q-14）。店舗値引き・見切り、EDLPマスタ、特売承認、電子値札、特売効果分析は本部特売機能の対象外。
