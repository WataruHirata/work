# セキュリティ・運用方針

## アクセス制御

- 入口の認証はv3と最新のユーザー指示に従う。店舗ポータル・店舗用メニューはログイン不要、上位機能は管理ログイン後のみ利用する。匿名で業務データを読めることを意味しない。端末・店舗の信頼できる所属識別が確定するまでは、未ログイン店舗画面は準備中表示とする。
- 管理ページはデータ取得前にサーバーで有効プロフィールとロールを検証する。APIも独立して認可し、CSV受付はservice_roleクライアント生成前に情報システム権限を検査する。管理メニューのボタン制御はRPC/RLSの権限判定を代替しない。

- 本部、エリア、店舗、担当売場のロールとデータ範囲を業務要求に合わせる。初期値は拒否とし、閲覧・更新・承認を分離する。
- API・帳票・CSV/PDF・バッチ・検索にも同じ範囲制限を適用する。画面で隠すだけの制御は禁止する。
- 店舗の共用PCでは個人を識別し、共有アカウントで重要な金額操作を記録しない。セッション期限とログアウト方針は認証方式決定時に定める。
- 店舗マスタ、権限、締め後修正の各管理者は要件書と承認済み決定に基づいて設定する。未確定の経理ロール等を仮定しない。

## データ保護とAI利用

- 秘密情報は承認されたSecret Storeまたは環境注入で管理し、リポジトリに保存しない。ローカル例は `.env.example` に架空値のみ記載する。
- 個人情報、実売上、顧客情報、資格情報、社外秘のファイルをAIサービスへ入力しない。AIツール・外部連携は組織の承認範囲とデータポリシーに従う。
- ログ・エラー・トレースには不要な個人情報、トークン、売上明細を含めない。
- 開発・テストには合成データを利用する。実データ利用が不可避な場合は、目的、アクセス、匿名化、保管・削除を事前承認する。

## 監査・依存関係

- 金額、価格、締め、修正、承認、返品、権限の実行主体・日時・対象・結果・変更前後を監査対象とする。
- 監査ログの改ざん防止、閲覧権限、保存期間、エクスポートを、法務・経理・情報システム部と合意する。
- 依存パッケージの更新と脆弱性対応を定期化し、ロックファイル、更新差分、ライセンスをレビューする。
- 脅威モデリングで権限昇格、他店舗データ閲覧、ファイル再送、二重計上、改ざん、漏えいを検討する。

## 運用・復旧

- POS未受信、形式不正、取込失敗、再取込、バッチ、特売適用・復帰を店舗・営業日単位で追跡する。
- 障害記録には対象、時刻、原因、操作者、影響、再処理、結果を残す。再実行は重複計上を起こさないことを確認する。
- 保存期間、監視時間、通知経路、稼働率、バックアップ方式、RTO/RPOは承認後に設定する。要件書の半日復旧は提案値であり確定SLAではない。
- 本番前にリストアと切戻しをリハーサルし、障害連絡先・責任者・エスカレーションを整備する。

## リスクのある操作

本番データ変更、削除、権限拡大、破壊的マイグレーション、外部へのデータ送信は、明示的な承認、対象確認、バックアップ・復旧計画なしに実行しない。開発環境でも実データや秘密情報を使わない。
