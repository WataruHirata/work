# 統合要件書v3と既存実装の照合

この台帳はルート再構成時点の照合記録です。その後に実DB接続、保存/承認/取込/外部連携境界を追加しています。現在の接続範囲・起動手順・残事項は [connected-backend.md](./connected-backend.md) を参照してください。全要件の受入完了を意味しません。

基準: [統合要件書v3](../みのり屋_販売管理システム_統合要件書_v3.md)、[画面遷移図](../画面遷移図1.drawio)。確認日: 2026-10-21。第25章の最新回答、今回のユーザー指示（店舗入口はログイン不要、上位権限利用時のみログイン）を優先する。

**完全実装とは判定できない。** DB/RPCとその試験がある機能も、実用画面・外部連携・運用・受入が未接続である。以下はソースと既存自動試験の照合結果であり、業務受入や実Supabase環境E2Eの成功を意味しない。

## 今回の変更

- 店舗ポータル `/` → 店舗用メニュー `/store` → 店舗5機能。管理者ログイン `/login?next=/admin` → 管理用メニュー `/admin` → 管理10機能。
- 管理入口はサイドバー下部。管理メニューは図の既存DBロールに対応し、利用できない機能を無効化。画面権限は機能の入口のみで、更新・承認は引き続きRPC/RLSで判定。
- 管理ページはデータ取得より前にサーバー認可。未設定時は管理業務を実行しない。未ログインの店舗ページは実データを返さない（端末・店舗の識別方式は要確認）。
- 空欄ログインとlocalStorageのdemo-authによる認証代替を廃止。ログアウト/戻り先制限、管理API/CSV受付のサーバー権限確認を追加。
- 既存5ページは管理側へ移動し、旧URLは対応する管理ルートへリダイレクト。未実装機能には準備中表示を置く。全業務機能の新規実装を行ったものではない。

## 照合の根拠

- D1: `supabase/migrations/202610200001_initial_sales_domain.sql`（組織・商品・売上・発注・通知・監査、RLS、締め/修正/承認/月次RPC）
- D2: `supabase/migrations/202610200002_campaign_management.sql`（複数商品、対象店舗、EDLP未確認拒否、店舗作業、監査）
- S1: `src/domain/sales.ts` と `src/domain/sales.test.ts`（営業日・税）
- T1: `tests/database-schema.test.ts`（RLS、一次/最終承認、月次確定拒否、特売基盤）
- A1: `src/domain/access-policy.ts`、`src/server/auth/admin-access.ts`、`src/domain/access-policy.test.ts`（管理入口・サーバー認可）
- U1: `src/components/admin/*-view.tsx`、`src/components/campaigns/campaign-management.tsx`、`src/server/actions/campaigns.ts`（画面接続状況）
- Q1: `src/server/queries/compatibility.ts`、`src/server/queries/dashboard.ts`（取得・架空データへの復帰）

「一部」は基盤・試験・一部処理がある状態。「未実装」は要件全体を満たす機能がない状態。「要確認/未検証」は確定待ちまたは実運用の証拠がない状態。DB列の存在だけでは画面や外部IFを実装済みにしない。
