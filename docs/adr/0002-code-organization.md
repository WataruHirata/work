# ADR-0002: 役割別の階層と機能別の画面構成

- 状態: 採用・実装
- 日付: 2026-10-21
- 根拠: ユーザーからの「一般的で、人間が整理・参照しやすい構成」への整理指示
- 関連: [ADR-0001](./0001-platform.md)、NFR-007/008、AT-10の保守・認可基盤

## 背景

`lib/backend` と `lib/supabase` に入力検証、業務手順、認証、DB接続が混在し、共通のServer Actionsも複数の画面ルート配下に置かれていた。さらに、設計資料には基盤採用前の説明が残り、実コードの責任範囲を把握しづらかった。

## 判断

Next.jsの一つのアプリを維持し、入口を `app`、表示を `components`、外部接続と独立した業務計算・契約を `domain`、サーバー手順を `server`、具体的な接続を `infrastructure` に分ける。表示設定は `config`、架空データは `mocks` に分ける。画面は機能別、Server Actionsは業務別の名前で配置する。

接続実装の選択は `server/container.ts` に集める。業務ルール・認可の既存SQLは移動・再実装せず、`supabase/migrations` の正本を維持する。コードの依存境界は構成テストで検査する。

## 選択理由

小規模なチームでも追いやすく、URL・配備単位を変えずに責任を明確にできる。接続契約がすでに存在するため、それを維持して具体的なDB実装だけを分離できる。Pythonの追加、フロントとバックエンドの別リポジトリ化、マイクロサービス化は今回の整理に含めない。

## 結果と検証

内部のインポートと参照資料を更新する。公開URL、依存パッケージ、業務条件、DBスキーマを維持する。既存の業務・権限・DBテスト、型チェック、Lint、Next.jsビルド、要件トレーサビリティ検査と追加の構成境界テストで確認する。

ファイル位置が変わるため、未マージの変更を取り込む場合は新しいパスへ合わせる。[コード案内](../code-map.md)を変更先の索引とする。
