# 本部変更指示・店舗通知

## 店舗から本部への売上修正依頼

FR-008/009/010/029、AT-04/05/10。売上画面で登録済み店舗端末の利用者が、個人ログインなしで営業日・修正後金額・理由を指定して申請する。翌日以降の申請はエリア一次承認待ちで保存し、エリア担当と店舗運営本部にアプリ内通知を作成する。本部への初回通知にも「一次承認待ち」と明示する。一次承認後は本部最終承認待ちの通知を本部担当へ作成する。承認・差戻しは管理ログインと既存の承認権限を必須とする。

本部の共通メニューと申請・承認画面には未読付きの通知カードを表示し、依頼を開くリンクで対象の修正申請・承認履歴に絞り込む。通知の既読と依頼の承認は別操作。承認・差戻しは既存の権限・段階検証を通し、最終承認時だけ売上を変更する。差戻しでは元売上を維持し、理由を結果通知に含める。結果は申請者の個人宛通知と店舗お知らせへ保存する。通知は申請・承認と同一トランザクションで作成する。

当日修正・月次確定後の制御は既存ルールを継続する。承認者の割当がない場合も申請レコードは承認待ちとして保持されるため、管理者が担当範囲と承認者を登録する。自動督促・代行承認のルールは確定していない。

プレビューでは売上→本部の申請・承認→店舗お知らせを同じタブ内で試せる。本部側の承認段階切替はデモ専用であり、実権限の切替は行わない。`src/mocks/corrections.test.ts` とDBテストで段階の飛越し・重複決定の拒否、最終承認前と差戻し時の売上維持、通知先の境界を検証する。

## 本部から店舗への指示

根拠: 統合要件書v3 25.6の追加回答。FR-020/028/029、F-10-030/031/035、AT-07/10。

商品本部は管理画面の特売管理から、商品・指示価格・実施日時（日本時間）・作業内容・対象店舗を指定して指示を発行する。既存特売は下書き確認・対象区分検証後の公開で通知する。特売の作業指示は期間付きの特売設定とは別であり、開始・終了・通常売価復帰は既存特売フローで管理する。

`send_store_instruction` は権限、有効商品、有効店舗、価格、重複対象を検証し、指示・店舗別対象・店舗お知らせ・監査を同一トランザクションで保存する。特売作業は既存商品マスタの対象区分が確認済みの場合だけ受け付ける。送信IDの再実行は同じ内容なら重複通知しない。異なる内容でのID再利用は拒否する。訂正する場合は新しい指示として発行する。

店舗の個人ログインではRLSで自店舗対象のみ参照し、確認者・確認日時を記録する。共用の接続済み店舗端末では既存の店舗お知らせ取得経路で通知の要約を閲覧し、確認登録は個人ログイン後に行う。確認は指示内容の受領であり、POS反映・値札変更の作業完了とは区別する。本部は店舗別未確認・確認済みを参照する。

通知はアプリ内で保存し、画面遷移・再読み込みで取得する。メール・プッシュ通知・自動ポーリングは追加しない。価格正本の変更・POS送信はこの指示発行では実行しない。POS接続仕様は既存の未決事項に従う。

DB未設定時は店舗5機能・管理10機能をプレビューで表示する。検索、状態・店舗絞り込み、詳細、デモ入力・状態変更が可能。本部変更指示のデモは同じタブのsessionStorageで保持し、対象店舗への通知・確認を画面間で試せる。一般テーブルへのデモ入力は画面内だけ保持する。デモ店舗の切替は表示例の選択であり、実際の店舗認証には使用しない。

検証: `tests/database-schema.test.ts` が権限外発行、対象店舗境界、二重送信、競合ID、店舗確認、監査、対象区分を確認する。`src/mocks/workspaces.test.ts` は機能網羅、絞り込み、対象店舗と確認の整合を確認する。ブラウザでは本部プレビューで指示を発行し、店舗のお知らせで対象店と対象外店の表示・確認後の本部状態を確認する。
